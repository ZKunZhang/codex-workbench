# Codex 工作台

在一个本地网页中查看与操作多个 Codex 会话。React + TypeScript 前端，Node.js 服务，通过 Codex App Server 的 Unix socket 或本机 WebSocket 连接。默认地址为 **http://127.0.0.1:4310**。

## 启动

需要 Node.js **22.12+** 和 **pnpm 12.10.1**（由 `packageManager` 固定）。当前协议类型由本机 **Codex 0.161.0** 生成并保存在 `server/protocol/`。沿用已有 Codex 登录、模型与权限配置，不需要另填 API Key。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

开发模式：`pnpm dev`。演示模式：`pnpm start --demo`；界面会明确标为模拟数据，操作不会影响真实会话。

日常常驻请使用上面的生产模式。`pnpm dev` 会加载 React 开发检查，任务多时更新耗时明显增加；执行 `pnpm build` 不会把正在运行的开发服务自动切换为生产模式，需要退出该工作台进程后运行 `pnpm start`，再刷新页面。

修改后端代码后需重新启动工作台进程；刷新网页或重新构建前端不会更新已运行的后台。页面检测到旧后台时会提示重启工作台，无需重启 Codex 服务。

默认连接 `${CODEX_HOME:-~/.codex}/app-server-control/app-server-control.sock`。先正常启动 Codex；工作台不自动启动、停止、更新或重启 Codex 守护进程。工作台退出时只关闭自己的连接，Codex 任务继续运行。

macOS 也可以双击项目里的 `start.command`，它会加载已有 Node 环境、构建并启动工作台。关闭该终端即可停止工作台。

## 使用

- 按项目、连接来源、关键词、状态筛选任务，收藏常用会话；待确认、待回答和异常优先显示。支持搜索 Session ID 和 CODEX_HOME，完整标识显示在右侧详情。点击“所有任务”会重置筛选。
- 子代理缩进显示在所属任务下面，并使用较轻的背景与标签；支持逐级展开、收起。搜索子代理时保留父任务上下文。
- 顶栏左侧可折叠、展开导航菜单，浏览器会记住选择；手机上也可以展开项目导航。
- 实时接收任务状态与权限请求。选中会话执行中每 3 秒刷新内容，空闲时每 30 秒、历史会话每 60 秒刷新；页面隐藏时暂停内容轮询，回到页面立即检查。长输出会截断，历史内容可继续分页加载。
- 已连接会话可发送指令；执行中可选择立即补充或加入下一轮队列。
- 停止只针对选定执行轮次，并暂停该会话的待发送队列；已完成的文件修改不会回滚。
- 历史会话只读取，不会因为查看详情自动开始执行。点击“连接会话”后才能继续对话。
- 会话详情右上角的“⋯”会话操作菜单提供“终端与面板交互”“退出面板连接”“关闭当前对话”。“终端与面板交互”显示连接原会话的命令；“关闭当前对话”释放当前页面内容，不影响任务。空闲时可退出面板连接：使用 `thread/unsubscribe` 取消订阅、暂停待发送消息并保留历史，工作台重连或重启也不会自动接回，点击“重新接入”可恢复。
- 退出面板连接不会终止其他 CLI。Codex 在最后一个订阅者退出且无会话活动后，按自身宽限期回收会话（当前官方文档为 30 分钟）；这不是立即释放 Codex 服务内存的接口。独立终端需要在原终端输入 `/exit`。执行中或仍有待确认请求时，先处理或停止后再退出。
- 顶栏“权限确认”集中展示当前收到的命令、文件修改、额外权限与用户问题，也会固定显示在当前任务的确认区，不随对话滚动而消失。权限批准只作用于本次/本轮，不提供一键全部批准。
- 顶栏“开启通知”可申请系统通知权限。授权后，收到待确认或待回答请求会显示任务名称，切到其他软件或后台标签页也会提醒；点击通知返回对应任务，同一请求不因重复同步而反复提醒，已处理通知自动关闭。通知设置中可发送测试通知或暂停提醒；浏览器标签标题也显示待确认数量。需保持页面打开，浏览器和系统允许通知；关闭页面、浏览器休眠或系统专注模式可能使通知无法及时显示。
- 新建会话时填写本机项目的绝对路径，继承 Codex 当前配置。
- 点击会话详情标题旁的铅笔修改标题，支持回车保存和 Esc 取消。标题不能为空，最多 200 字符；保存到对应 Codex 来源后，任务列表与详情同步更新。历史会话和子代理也可以改名，无需恢复执行。
- 在左侧任务列表或会话详情右上角点击垃圾桶，确认后永久删除该对话及其子对话，同时清理相关队列与收藏。正在执行的会话或子对话必须先停止。使用官方 `thread/delete` 接口，不直接删除数据库；失败会保留错误提示，结果不确定时暂停队列以免继续发送。

**会话状态与终端进程不同。** 对配置了 CODEX_HOME 的本机来源，通过 `lsof` 检查当前用户 Codex 进程打开的 writer-lock 文件，识别仍被独立终端持有的会话；单独存在的锁文件不代表进程还在运行。独立终端会话标明 PID，自动读取最近执行状态与内容，不显示“连接会话”，也不尝试恢复到另一个服务。其发送、停止、删除和权限确认需在原终端完成。无法检查本机进程时会显示诊断提示。

`历史记录` 表示会话未加载在所连接的服务中，且没有识别到独立进程持有；未知 CODEX_HOME 或平台缺少 `lsof` 时，仍不能据此断言原终端已退出。`空闲` 表示当前没有执行轮次，具体结果显示在详情的“本轮已完成 / 本轮已停止 / 本轮执行失败”中。

## 接入范围

默认发现共享 Codex 服务中的活动会话，以及该服务可读取的历史。自动遍历所有任务分页和已加载会话分页，并定期同步；列表不再限制前 100 条。子代理默认展示，可关闭列表上的“子代理”选项。已归档、已删除会话不在任务列表中。多个来源的任务会标明所属连接。

本机来源还会定期核对 `sessions/` 中的 rollout 文件名，对旧版本列表接口遗漏的会话逐个调用 `thread/read` 补入；不因补入记录而恢复或执行会话。不会直接编辑 Codex 数据库。

### 磁盘读取与刷新

- `sessions/` 首次建立内存索引，之后监听文件增删并只检查变化路径。日志内容追加不触发目录扫描；无变化时复用索引。每 15 分钟全量核对一次以补偿遗漏事件；平台不支持监听时降级为每 60 秒扫描。索引只读文件名与元数据，不读 rollout 内容。
- 已加载会话列表每 5 秒检查，完整历史列表每 60 秒核对；连接恢复与手动刷新立即核对完整列表。未查看的独立终端会话每 30 秒检查执行状态，当前查看的会话保持每 3 秒刷新。
- 内容请求按来源、连接代次、会话与分页游标缓存，最多保留 16 页，缓存中的正文文本估算上限为 8 MiB（并非整个进程内存上限）。重复并发请求合并，通知和操作使对应缓存失效；手动“刷新会话”绕过缓存。缓存仅在内存中，不另写索引文件。
- 本机进程检测结果复用 10 秒；发送、接入、停止和删除前仍检查最新进程与会话状态，权限请求和回复不经过详情缓存。
- 同步时间、后台同步标记及 token 用量变化不再单独广播整份列表；任务、连接、队列与权限变化继续推送。前端复用未变化的任务和消息，只重绘变化的行；相对时间每分钟更新，页面隐藏时停止时间刷新。

减少读取的代价是未打开的历史信息可能延迟最多约一分钟更新；目录监听遗漏时由定期核对修复，也可以手动刷新。前台执行中的对话与权限确认保持原有更新通道。

页面仅保留当前一页、最多 60 条消息，历史使用“更早一页 / 较新一页 / 回到最新”导航，不再无限追加。浏览历史页时暂停详情轮询。折叠的工具输出展开后才渲染；超过 4,000 字符的代码块保留完整文本与复制功能，但跳过语法高亮，减少节点数量。文字增量不再触发整个任务列表推送，任务状态和权限请求仍正常推送。这些限制控制额外分配，不代表实测的整机或真实工作台内存占用。

不同 `CODEX_HOME` 有独立的服务与历史，需要添加对应来源。在本项目 `.workbench/sources.json` 中保存额外来源，启动时会与默认来源一起连接（该文件不提交到 Git）：

```json
[
  {"id":"second","name":"第二个 Codex","codexHome":"/Users/你的名字/Workspace/codex-api-config"}
]
```

`codexHome`、`socket`、本机 `ws://` 地址 `url` 三选一。改动后重启工作台；不会修改 Codex 本身的配置，重复 socket 会合并。也可以用环境变量完整指定来源列表，覆盖默认来源及上述文件：

```sh
export CODEX_WORKBENCH_SOURCES='[
  {"id":"local","name":"本机 Codex","socket":"/Users/你的名字/.codex/app-server-control/app-server-control.sock"},
  {"id":"second","name":"第二个服务","url":"ws://127.0.0.1:4500"}
]'
pnpm start
```

连接配置只影响工作台。不要用新服务同时恢复另一服务仍在运行的同一个会话。运行中会话的自动订阅只加入原服务已经加载的会话，不覆盖模型、权限或工作目录。

## 断线、队列与审批

- Codex 连接自动重试；断线时显示“状态未知”，禁用控制操作，清除该连接上的过期审批。
- 浏览器刷新会重新获取当前待处理事项。Codex 服务本身断线后，协议未保证重放悬挂的审批请求；如果只有“等待确认”状态而没有请求内容，会提示回到原终端处理。
- 队列和操作记录存储在本项目 `.workbench/state.json`，采用原子写入和仅当前用户可读写的权限。浏览器收藏使用本机浏览器存储。
- 发送超时或进程重启时，正在发送的消息标为“发送结果待确认”，不会自动重发。确认会话内容后，可以移除本地队列记录；移除不会撤回已送达消息。
- 队列发送前会再次检查会话是否空闲。当前协议没有跨客户端的“仅在空闲时启动”原子条件；多个控制端同时给同一会话发消息仍可能产生竞争，建议同一会话只使用一个控制端安排下一轮。
- MCP 结构化表单、动态工具和客户端认证请求仍需在原终端处理；工作台不会伪造批准或代替原客户端执行这些工具。

## 本地访问与数据

服务固定监听 `127.0.0.1`，默认端口 `4310`（可用 `PORT` 修改）。HTTP 校验 Host、Origin 与 Fetch Metadata；写操作和浏览器 WebSocket 需要当前服务生成的令牌。不提供任意 shell 执行接口。

工作台不读取 `auth.json`，不直接编辑 Codex 数据库或共享配置。对话内容按纯文本显示，不执行会话里的 HTML。发布静态资源时不会暴露项目源码、环境文件或 `.workbench/`。不要将本服务直接暴露到公网。

## 验证与维护

```sh
pnpm test                    # 状态、权限、队列和错误恢复测试
pnpm build               # TypeScript 检查与生产构建
pnpm exec playwright test         # 使用明确标识的演示服务验证浏览器交互
pnpm test:e2e --config playwright.offline.config.ts # 离线验证列表删除、标题与布局，不启动服务（先 build）
node scripts/live-smoke.mjs # 已启动工作台的只读连接自检
```

`node scripts/live-smoke.mjs --exercise` 会创建一个独立测试会话，在临时目录发送一条禁止调用工具的自检指令，并检查回复；会消耗少量当前 Codex 账户额度，不会操作已有任务。

Playwright 首次使用如缺少浏览器，运行 `pnpm exec playwright install chromium`。浏览器测试使用端口 `4311`，不会向真实 Codex 发送控制指令。

升级 Codex 后，可先运行 `codex app-server generate-ts --out <临时目录>` 对照接口。协议目前为实验性接口；已有测试覆盖本项目所用字段，未知能力会降级提示，不会自动修改本机 Codex 配置。

协议依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)及本机 0.161.0 生成的类型。文档里的更新接口不一定适用于本机版本。
